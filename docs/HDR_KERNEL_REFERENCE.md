# HDR numerical foundation and support boundary

2026-10-12. Upstream source: `f5ae5bad0b25b32dda9f254e62d2f07f59478698`.

`src/shared/hdr-pixels.ts` uses dense top-left **Float32 premultiplied extended-sRGB** working buffers. A value of 1 is encoded white; finite RGB can be negative or brighter than alpha/white. Alpha must be finite within [0,1]. Fully transparent nonzero RGB (emissive EXR pixels) is currently refused explicitly because this editing representation cannot preserve that separate emission component. This differs from the UNORM16 invariant RGB<=alpha. Never route HDR through UNORM16 spatial operations or implicitly clip RGB to alpha.

Binary16 is a storage/reference boundary: `halfToFloat` and `floatToHalf` implement IEEE binary16 including signed zero and subnormals, with round-to-nearest ties-to-even. The scalar functions expose NaN/Infinity patterns; raster codecs refuse nonfinite inputs. `decodeHDRHalf` and `encodeHDRHalf` preserve source storage and validate before allocating their output. Saving finite values outside the representable half range ±65504 fails explicitly, rather than writing Infinity. Float32 intermediate work is not rounded to half after every operation.

The numerical APIs are `normalizeHDR`, `restoreHDR`, `applyHDRExposure`, `applyHDRColorFilter`, `takeHDRPainted`, `extractHDRAlpha`, `restoreHDRAlpha`, `hdrPeak`, and `quantizeHDRPreview`. Normalize follows native `deep_hdr_normalize`: divide RGB by alpha, clamp negative straight colors to zero, find the RGB triplet's peak or 1, normalize to premultiplied UNORM16, and save the scale. Restore multiplies those premultiplied UNORM16 results by the saved scale. This bridge is used for the eight supported color operations except Exposure. It has native normalized16 precision and native loss of negative values; spatial operations must not use the bridge.

Exposure uses the mirrored, extended sRGB transfer function, evaluates the linear exposure factor/offset/gamma without clipping at white, and multiplies by the original alpha. Stage 2 intentionally departs from native Compositor's `max(0, linear)`: Gamma now applies a sign-preserving power to negative linear values, following [Adobe HDR Exposure](https://helpx.adobe.com/photoshop/using/adjusting-hdr-exposure-toning.html). This is a documented semantic alignment, not yet a captured Photoshop negative-pixel reference. Default parameters return an exact copy, including signed zero. Colors over white remain stored; reducing exposure can reveal their detail. Ordinary native HDR Paint merge retains each unchanged Float32 pixel exactly and replaces a changed premultiplied proxy pixel with fresh paint bytes divided by 255. The returned working pixel has full Float32 precision; only serialization rounds to half.

`src/core/hdr-composite.ts` implements full-grid Float32 HDR composition, visible same-parent contiguous clipping stacks with float alpha extraction/restoration, pass-through groups, group/raster mask density/feather/placement, supported color adjustment opacity/order, affine image sampling, mixed HDR/UNORM16/PNG8 source lifting, and readonly viewport sampling. The first explicit HDR blend matrix is **Normal, Multiply, Darken, Lighten, Linear Dodge (Add), Difference**. Their extended-domain algebra has no white clamp. Other blend modes, raster effects and unbaked Photoshop vector masks fail preflight. The separate UNORM16 compositor's 24 modes remain a separate capability. This matrix is a portable implementation with mathematical tests, not a claim that all macOS Core Graphics/Metal composition edge behavior has been independently measured.

Only `quantizeHDRPreview` applies SDR clipping, then the existing deterministic native UNORM16 dither and straight PNG boundary. This is the ordinary SDR display/export representation; it does not claim EDR display output. Over-white source values survive preview. The native dither may produce 254 at an opaque white sample; tests therefore check clipping range and preserved source rather than force one display byte.

## Independent native reference

`scripts/create-hdr-reference.py` compiles unchanged upstream `DeepPixels.c` using the installed MacOSX26.5 SDK and `-O2 -ffp-contract=off -fblocks -dynamiclib`. `fixtures/parity/native-f5ae5ba-hdr.json` records exact commit, source SHA-256, SDK and flags. The generator calls original C kernels through ctypes and never calls production TypeScript.

Eight dense input cases contain **1,440 pixels / 5,760 channels** per operation, including encoded RGB over white, finite negative RGB, alpha zero, minimum half subnormal alpha, half normal transition, fractional alpha, and a 73-row parallel job. The following are independently compared: normalized UNORM16, brightness scales, peak, restored half storage, extended Exposure half storage, changed-paint half storage, alpha-extracted half storage and restored alpha half storage. The original upstream parity run recorded **max difference 0** across these comparisons. Stage 2 keeps the unchanged C fixture but compares Exposure only where post-EV/Offset linear RGB is nonnegative (one-half-ULP portability limit); negative linear values now intentionally follow Adobe's sign-preserving Gamma rather than the C fixture's zero clamp. Separate signed algebra and identity tests cover that extension, without labeling them Photoshop output.

The 63,488 finite binary16 bit patterns also round-trip exactly through scalar encode/decode. The original foundation run of `tests/hdr-pixels.test.ts` and `tests/hdr-composite.test.ts` passed **50/50** together, and focused strict TypeScript validation passes. Core tests include mixed layouts, over-white/negative source-over, all six blend equations, masked adjustments, opacity, float clipping alpha, pass-through groups, affine flip/translation, high-precision viewport, hidden parents, unsupported appearance preflight and immutable buffers.

Memory/pixel/compute budgets are enforced before full-grid work. The common limits are 32 million pixels / 512 MiB, including retained source/proxy buffers, composed surfaces and adjustment work; the compositor bounds sampling work to 240 million weighted source/mask samples. Invalid or oversized work does not partially install an asset. Actual import, `.comp` v13 half storage, EXR/Radiance I/O, command transactions, spatial HDR edits, package/runtime/UI and EDR display are separate integration gates owned by the main task.
