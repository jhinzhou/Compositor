# RGBA16 Paint / Smudge / Liquify reference and acceptance scope

2026-10-12. Fixed upstream commit: `f01e2980fb76eb085d3f8ac96070a1c0c4a9afa9`.

The image asset remains dense, top-left, premultiplied encoded-sRGB RGBA16. The two pure preparation APIs in `src/core/deep-stroke-edit.ts` return owned changed pixels, dimensions, placement, and optional carried grayscale mask; they do not install assets, change history, or mutate source buffers. A strict no-op can return the original immutable source buffer. The Editor installs the result through the existing revision-checked document transaction.

## Ordinary Paint and Erase

Current Photoshop research batch: `prepareDeepPaint` uses the shared brush coverage/dynamics and selection, then composites directly into original premultiplied RGBA16 through `src/core/high-depth-paint.ts`. With source opacity `a = colorAlpha × coverage × selection × toolOpacity`, Paint writes `RGB = colorRGB × a × 65535 + sourceRGB × (1-a)` and `A = a × 65535 + sourceA × (1-a)`, rounding once to UInt16. Erase scales every original premultiplied channel by `(1-a)`. No PNG8 preview is used as the editing source. Unselected and unhit samples remain exact; source bytes and previews remain immutable until the command transaction creates the new asset.

This deliberately improves on the previous native Compositor `deep_take_painted` bridge. Before this change, any changed display-proxy pixel was replaced completely with RGBA8 ×257. On an opaque source `[10001, 20002, 30003, 65535]`, a full-coverage black brush at command opacity `.001` previously made no change; direct compositing now gives `[9991, 19982, 29973, 65535]`, and erase gives alpha `65469`. These sub-byte tests verify source arithmetic, **not a Photoshop `.1%` brush-output reference**: native Photoshop's tested UI/script Opacity has integer-percent behavior and `.1%` was observed to resolve to zero. Real native brush comparisons must use supported native parameters and recorded tip settings.

The geometry, Flow, pressure, smoothing, selection and tip rasterizer remain the shared brush path; this change does not claim Photoshop private brush-tip equivalence. Trim decisions use true RGBA16 alpha, including original alpha 1. Linked grayscale masks follow grow/trim geometry; separately placed/unlinked masks keep their placement. Masks themselves remain PNG8 and use the existing mask path. The current layer lock schema supports all/position locks, not a separate Brush Lock Transparent Pixels option; existing all-lock enforcement remains in Editor before preparation.

The retained `takeDeepPainted` helper and its unchanged upstream C fixtures below are historical/native kernel compatibility evidence. They are **not the current direct-precision brush commit oracle**.

`fixtures/parity/native-f01e298-deep-paint.json` contains **32 independently generated C cases / 6,000 pixels / 24,000 channels**, including low/zero alpha, complete no-op, alpha changes, opaque boundaries, and 73-row jobs exercising native parallel rows. `scripts/create-deep-paint-reference.py` compiles **unchanged** upstream `DeepPixels.c` with `xcrun clang`, `-O2 -ffp-contract=off -fblocks -dynamiclib`, using the installed MacOSX26.5 SDK; 27 was not used. The fixture records source SHA-256, exact commit, SDK and flags. No TypeScript production function is called by the generator. The tested comparison has **max channel difference 0**. This proves the merge kernel contract, not that every Core Graphics brush rasterization pixel equals the portable brush implementation.

## Smudge and Liquify

`warpDeepPremultiplied` is a Float32 scalar port of the equations in native `Compositor/Rendering/MetalWarp.swift`. Its document grid keeps original RGBA16 values throughout the warp. Smudge carries Float32 four-channel tip samples between dabs. Liquify keeps an immutable original color raster, a persistent Float32 source offset field, and a copied pre-dab offset ROI; each push interpolates offsets, moves them backward by the brush's travel, then draws from the untouched original through that offset. It does not interpolate the previous dab's color result. A sharp-boundary two-dab test distinguishes the original-once method from progressive color blur.

The native `WarpStroke.append` dab planning is preserved: minimum diameter 2, capped hardness .98, spacing `max(1, diameter * .005)` for Smudge and `.025` for Liquify, and the same rounded dab centers. Native strength has a .01 minimum; our existing command contract treats explicit opacity 0 as a strict no-op before calling the kernel. Native finishWarp (`Compositor/Document/SmudgeLiquify.swift:240`) commits actual dab points with an enlarged `diameter+4` hard tip, opacity 1, and replacement mode; original strength is not applied a second time.

`prepareDeepWarp` only writes selected pixels where the warped document sample actually differs from the pre-warp sample. All other source-grid samples stay byte-for-byte RGBA16 exact, including an affine placed layer whose document work copy involved interpolation. Selection masks and final tip coverage are applied once during commit. Document pixels are sampled transparently with the same half-pixel convention as the existing retouch path; native Core Graphics placement/sampling can still differ at edge footprints.

**Protect Alpha is intentional behavior improvement:** our pre-existing PNG8 Smudge path only used the flag to prevent growth. Native Smudge itself does not expose that flag: finishWarp uses replacement/copy (`BrushStroke.drawClone`, `BrushStroke.deepPainted`). On the new RGBA16 path `protectAlpha=true` preserves each original alpha channel exactly, normalizes warped straight color back under that original alpha, and leaves fully transparent pixels transparent. False allows alpha to move and permits grow/trim. Thus the portable Protect Alpha feature is useful and correctly named, but should not be described as native Smudge parity for an upstream flag that does not exist.

`fixtures/parity/scalar-f01e298-deep-warp.json` contains **16 independent Python Float32 scalar cases / 2,288 pixels / 9,152 channels** from the shader equations, including normalized rgba16Unorm texture reads, reverse-direction strokes, fractional centers, strengths, hardnesses, sharp color edges, and low/zero alpha. The generator `scripts/create-deep-warp-reference.py` does not call TS. It includes the SHA-256 of both native Swift source files. The portable integer-unit color evaluation versus the independent normalized-texture evaluation has **max channel difference 1 of 65,535**, in one Liquify case; all other cases have difference 0. Tests enforce that limit and exact dab plans.

**This scalar reference is not native Metal GPU execution.** GPU texture conversion, fast math and platform floating-point scheduling remain a separate native GPU oracle gate; no byte-exact native GPU claim is made. CPU fallback in native WarpStroke is PNG8, so the portable RGBA16 scalar path preserves precision where native fallback would not.

## Refusal, budgets and verification

These APIs require a genuine valid premultiplied RGBA16 image asset. Mask targets, image groups, adjustment layers, non-smear retouch kinds, and Sample All Layers are explicitly refused. Other retouch functionality is handled outside this module. Invalid dimensions, unaligned samples, non-finite action parameters and straight-alpha data are refused. Preflight includes retained asset bytes, proxy pairs, expanded/cropped source grids, document sampler and warp buffers, copied offset scratch, carried tips and linked-mask storage. The limit is 512 MiB and 32 million pixels. Dab planning is limited to 100,000 dabs and 80 million visited tip pixels; rejected work does not install an asset or partially edit the source.

Historical alpha.15 focused source validation: `npx tsx --test tests/deep-stroke-edit.test.ts` — **60/60 passed**. It verifies independent native C paint merging, independent scalar warp cases, native replacement footprint, shared brush dynamics, non-257 precision, alpha1 preservation, selection/rotation/flip/local-only edits, atomic refusal, mask carry, true-alpha trim, source/proxy immutability, no-op identity and persistent original sampling. Full package, UI, save/reload and undo/redo evidence belong to Root's unified phase-2 gate.


## Explicit Photoshop soft-tip growth

`brushModel:'photoshop'` is forwarded through high-depth paint preparation. An omitted model retains the legacy coverage path. The measured Photoshop shoulder family uses sigma0 `diameter × 15/64`, a continuous hardness-dependent core/width and a fixed 4-sigma0 footprint for hardness<1; source growth therefore reserves effective extent diameter `nominal diameter × 1.875`, not just the cursor's nominal diameter. Original source precision compositing and carried-mask rules are unchanged. The dedicated `high-depth-soft-tail.test.ts` exercises RGBA16 and HDR tails at 21 px from a 32 px brush center, outside the nominal 16 px radius, including sub-byte tail Alpha, preview/commit equality and exact source Undo/Redo.

The independent measured candidate report is `artifacts/photoshop-native/measurements/soft-tip-candidates/comparison.json`. All 10 soft references improve with one Gaussian rule across 32/48/64 px, but this is approximate Alpha alignment, not private Photoshop brush reproduction. The Flow20/Spacing10 32 px native sample retains max Alpha error 36; its 160 px path length is an exact multiple of 3.2 px spacing, so endpoint policies coincide and cannot explain this residual. Hardness50, texture and pressure still need separate native evidence.
