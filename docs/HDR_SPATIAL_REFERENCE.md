# HDR spatial editing support and numerical evidence

2026-10-12. Native source `f5ae5bad0b25b32dda9f254e62d2f07f59478698`.

The new spatial APIs are `prepareHDRStroke(stage, action)` for image Paint/Erase, Blur, Smudge and Liquify, and `bakeHDRImageSizeRaster({hdr,width,height}, transform, sx, sy, sampling)` for Image Size. They return dense premultiplied extended-sRGB Float32 pixels, dimensions/placement, and optional carried grayscale linked mask. They never install assets or alter history. `sampleHDRLayerInDocument` and `sampleHDRBilinear` share the half-pixel coordinate convention. Changed results own their buffers; a strict no-op can return the original readonly source.

Current Photoshop research batch: Paint/Erase retain shared coverage/dynamics/selection but use `src/core/high-depth-paint.ts` to composite original premultiplied Float32 samples directly. With effective source opacity `a = colorAlpha × coverage × selection × toolOpacity`, Paint writes `RGB = colorRGB × a + sourceRGB × (1-a)` and `A = a + sourceA × (1-a)`; Erase scales all source channels by `(1-a)`. Writes round to Float32, never to an SDR display byte. This intentionally improves on native Compositor's `deep_take_painted_hdr` display-proxy bridge. Original negative/overwhite contributions now survive at partially painted or erased hit pixels, not only at unhit pixels. Example: black brush opacity `.1` over `[2, -.25, .5, 1]` preserves `[1.8, -.225, .45]` (Float32 rounding); the previous proxy bridge produced approximately `[.898039, 0, .450980]`.

True Float32 alpha governs trimming, including alpha `2^-24`; linked raster mask coverage follows grow/trim geometry. Masks remain PNG8 on the existing mask path. Source/preview/Undo state tests include fractional alpha and exact original asset restoration. Opacity `.001` tests are command precision checks, not native Photoshop `.1%` output parity: tested native brush Opacity resolves that fractional percentage to zero. Current brush geometry/spacing/dynamics still require separately recorded Photoshop reference outputs.

Blur uses one original Float32 snapshot and an independently verified integrated Gaussian. It filters original extended RGB/alpha directly and does not normalize colors or clamp them at white. Protect Alpha preserves each original source alpha exactly; false permits coverage growth with floating alpha. Source-over brush commit uses the existing brush geometry, selection and opacity once. Duplicate points do not reblur a source within one stroke.

`src/shared/hdr-warp.ts` follows the new native MetalWarp `steps=0` path: Smudge carries Float32 colors, and Liquify moves persistent Float32 offsets while sampling immutable original colors once. Neither rounds to UNORM16 nor clips extended RGB. Source alpha stays within [0,1]. `prepareHDRStroke` commits with native enlarged hard replacement tip and selects only actual changed document samples; untouched source-grid samples never undergo a whole-layer projection. Protect Alpha is the explicitly documented portable improvement from DEEP_STROKE_REFERENCE: it preserves the source alpha for every pixel, including transparent/subnormal coverage, and adjusts warped straight color under that alpha. This flag is not exposed by native Smudge. Sample All Layers, mask targets, clone/healing and non-image targets are explicitly refused by this module rather than silently downgrading them.

Image Size preserves native placement/rotation/flip/anisotropic baking geometry. Nearest identity and integer enlargements keep source Float32 samples exactly, including signed zero, minimum half subnormal alpha, negative RGB and values greater than white. Smooth samples premultiplied Float32 directly. High quality reductions use true Float32 Lanczos halvings with odd-size source phase. Source RGB is never clamped to alpha or normalized per pixel; alpha is bounded and newly transparent samples are zero. This is a precision improvement over native DownsampleCache's documented byte allocation and is not an assertion of private Core Graphics color-resampling equality.

Independent evidence:

- The original C paint merge/alpha/exposure references in `native-f5ae5ba-hdr.json` remain a separate exact half-storage boundary oracle.
- `scalar-f5ae5ba-hdr-warp.json` has **16 independent Python Float32 shader-scalar cases, 2,288 pixels and 9,152 channels**. The script calls no production TS and records native MetalWarp/SmudgeLiquify source SHA-256. Tested Float32 buffers and dab plans are **exact, max difference 0**. These are an independent scalar port of the native `steps=0` equations, **not native Metal execution**. Native `rgba16Float` texture writes may round to half each dab; the portable path deliberately retains Float32 during a stroke, so no native GPU byte-equivalence claim is made.
- Blur compares with independent 256-subinterval Simpson integration and separable scalar filtering, within `2e-5` encoded Float32 units.
- High quality reduction compares with independent direct 2D Lanczos (no production kernel/pass), within `2e-6` units.
- Thirty-two independently measured native CG affine footprint references are reused solely for placement/Nearest geometry. There is one native tie discrepancy at an exact rotated source-pixel edge, which is explicitly accepted and identified by source coordinates; these references are not HDR GPU color outputs.

Historical alpha.16 focused validation: **32/32 tests passed** across `hdr-stroke-edit.test.ts` and `hdr-resample.test.ts`, with strict TypeScript validation. Alongside the 50 HDR foundation tests, the current numerical source scope is 82 tests. Source/proxy/mask/manifest immutability, atomic invalid/budget refusal, local selection, affine placement, grow/trim/mask carry, no-op identity and original-once Liquify are covered.

Working memory is bounded to 512 MiB with 32 MP per surface, retained original/proxy bytes, expanded/cropped Float32 pixels, selection coverage, mask carry, document work canvas, offsets/scratch/carried tip, and convolution or resampling scratch. Warp planning also caps 100,000 dabs / 80 million tip visits; blur/resampling preflight caps 500 million work operations. Unsupported or oversized work does not modify source buffers. Import/EXR/Radiance, `.comp` half storage, revision binding, undo/reload, editor dispatch, preview and packaged UI acceptance are main-task integration gates.


## Explicit Photoshop soft-tip growth

`brushModel:'photoshop'` is forwarded through high-depth paint preparation. An omitted model retains the legacy coverage path. The measured Photoshop shoulder family uses sigma0 `diameter × 15/64`, a continuous hardness-dependent core/width and a fixed 4-sigma0 footprint for hardness<1; source growth therefore reserves effective extent diameter `nominal diameter × 1.875`, not just the cursor's nominal diameter. Original source precision compositing and carried-mask rules are unchanged. The dedicated `high-depth-soft-tail.test.ts` exercises RGBA16 and HDR tails at 21 px from a 32 px brush center, outside the nominal 16 px radius, including sub-byte tail Alpha, preview/commit equality and exact source Undo/Redo.

The independent measured candidate report is `artifacts/photoshop-native/measurements/soft-tip-candidates/comparison.json`. All 10 soft references improve with one Gaussian rule across 32/48/64 px, but this is approximate Alpha alignment, not private Photoshop brush reproduction. The Flow20/Spacing10 32 px native sample retains max Alpha error 36; its 160 px path length is an exact multiple of 3.2 px spacing, so endpoint policies coincide and cannot explain this residual.
